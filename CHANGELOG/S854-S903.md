### S855 — 2026-10-21 — IMS and Suite "build next" in one release: report pages start at once, Item Master paints first, the app keeps its unchanged files, the count-device screen, the Owner Report supplier split

Every IMS and Suite item the owner marked "build next" on 2026-10-21 (S853), in one session: four helpers on
separate files, then three helpers converting the period pages in batches, the shared month list by the lead,
one test run, one build, one release (crest-v470). No migration and no Edge Function deploy.

**Owner decisions (asked in plain words):** build all of it in one release; the Owner Report supplier columns
before VAT and adding up to Net Spend, as on the Vendor Report; regenerate the eight frozen owner reports
again once the release is live (CASA ACAI CAFE Jestha 2083 stays as made).

- **Report pages start at once (PERF-2).** `src/shared/periodList.js` keeps one month list per client
  (`monthly_periods`, named columns, newest first), read by Layout on mount, shared while in flight, never
  stored from a failed read or from a read that started before a write. `initPeriodLoad` + `usePeriodList()`
  start a page's load from the list in memory beside a fresh read, re-pick if another device moved the
  month, and hold the loading state until both land; a month picked before the fresh list lands still gets
  its fresh row. Close, reopen, rename, create (`closePeriod.js`, `Periods.js`, `AdminClients.js`) and
  restore drop the list; `sessionDataCache` clears it on sign-out or another user (`onPageCacheClear`).
  Converted: Monthly Summary (the pilot), 13 more reports, 8 stock and variance pages, Purchases, Purchase
  Orders, Sales, Requisitions, the three menu reports and two dashboard widgets. Chained period effects are
  gone (Best Sellers, VAT, Non-VAT, Dead Stock, Wastage, the menu reports); on an entry page the guessed
  month only starts the reads, and the dropdown, the lock and every save take the fresh list. Stock Count
  keeps its own read (its offline month copy and queue flush come first). The header chip now follows a
  close or reopen. Left on their own reads: the main Dashboard, the Owner Report, Consolidated P&L and the
  group pages (other columns, or more than one outlet).
- **Item Master shows its list first (PERF-3).** The usage scan runs beside the list as pending / ok / failed;
  `deleteGuard` (`itemDeleteGuard.js`) refuses Delete until it answers, the unit stays locked and the Used In
  filters stay on All until the first full answer, "checking…" is announced once, and the failure banner
  shows only on a failed scan (a failed scan no longer makes Unused list every item). A new item code never
  comes from the filtered list while the item book is loading.
- **The app keeps unchanged files across releases (PERF-4).** Measured live first: `/static/` is served
  `s-maxage=31536000, immutable` and a missing hash is a 404, so the re-download came from the worker. A
  fixed `crest-static` cache holds `/static/`; each release keeps the new build and the one before it and
  prunes the rest, and skips the prune whenever a build list is missing (keep, never wipe). The first
  rollout copies files out of the old `crest-v*` cache, so even this release is not a full download.
  `CACHE_NAME` still bumps for the shell and unhashed files.
- **Stock-count device screen.** `DeviceGate` (from the till's `TillGate`) fronts both: numbered steps
  (Stock Count → Settings → Show setup QR, scan within 15 minutes), who can do it, the support line, and the
  signed-out or expired-code message as an alert.
- **Unsaved dish photos.** `useUnsavedDishPhotos` releases a new recipe's uploads on Cancel, Back or leaving
  without saving, through the same last-link check.
- **Budget vs Actual.** The open-month line says actual net purchases read low until every bill is in (the
  page measures purchases; D30 forbids a food-cost label on them).
- **Owner Report supplier table (schema version 19).** Cash, Credit and FonePay are after discount and before
  VAT through the Vendor Report's own helper, moved to `vendorNetBasis.js`, so they add up to Net Spend; a
  FonePay column, Total-row splits and a Tip saying Unpaid Credit includes VAT. Older snapshots say their
  split was before the discount. A supplier with only returns now gets a row, and an all-free bill no longer
  goes negative, both as on the Vendor Report. The aging half of the backlog item was already fixed in S849.
- **Terms screen (Suite).** `LegalReacceptance` tells a first acceptance from a changed document by the
  outlet ledger (`legalAccepted`, now on the auth context), per document, with a mixed sentence when both.
- **Docs:** Help (Item Master, recipes, the counting tablet, Budget vs Actual, the Owner Report) and the IMS
  and Suite guides; rules `frontend-performance.md`, `offline-and-cache.md`, `staff-app.md`,
  `component-library.md`, `recipes-and-subrecipes.md`, `owner-report.md`, `vendor-payables.md`,
  `legal-documents.md`; `IMS_TODO.md` PERF-2/3/4 and the four ⚪ items ✅, `SUITE_TODO.md` the legal item ✅
  and the regenerate task. Both rules-load warnings predate this release (POS +16.0%, pages +45.6% at S854); it
  adds about one point to each.
