### DOCS-7 [P3] A Crest Staff swap refused without a code shows 'Try again', and trying again fails the same way
- Where: live `request_shift_swap` and `respond_shift_swap` (plain-text RAISEs). src/shared/errorText.js:995-998 (FALLBACK). src/modules/hr/selfservice/SelfServiceHome.jsx:399-401 (respondSwap returns on error without reloading) and :601-602 (Accept/Decline buttons with no busy state).
- What happens: the most likely case is a double tap. A coworker taps Accept twice, or on two devices. The first call succeeds ('Accepted — your manager still has to approve'), and the second is refused with 'request is no longer pending'. errorText has no rule for that text, so the phone shows 'That didn't work. Try again — and tell your manager if it keeps happening', and the card stays on screen because respondSwap reloads only on success. A rarer case: the manager moves a waiter's Friday shift while the waiter has Request Swap open. Send is then refused with 'you have no shift on that day', and every retry fails the same way. No data is lost, but the retry advice is always wrong in these cases.
- Evidence: live pg_proc. request_shift_swap raises plain 'cannot swap with yourself', 'coworker not found', 'you have no shift on that day' and 'coworker has no shift on that day', next to its coded refusals (swap_day_past, swap_day_unpublished, swap_day_taken, swap_already_requested). respond_shift_swap raises plain 'request not found' and 'request is no longer pending'. Plain 'not authorized' matches the :354 rule ('Your self-service access isn't set up'), which is right for the caller-not-linked case. 'not authorized for this request' also matches it, but the UI cannot reach that case, because the list shows only requests aimed at the caller. errorText already has `swap_not_pending|swap_not_found` (:921) and `swap_shift_changed|swap_shift_missing` (:926) rules, written for approve_shift_swap. hr-payroll.md covers only the coded swap refusals.
- Status: new.
- Fix: disable Accept/Decline while a call is in flight, and call `loadSwapRequests()` in respondSwap's error branch. Add errorText rules matching 'no longer pending|request not found' and 'no shift on that day'. Alternatively, have the next swap migration raise the existing codes (swap_not_pending, swap_not_found, swap_shift_missing), so the current staff wordings apply with no errorText change.
- Confidence: confirmed in the live catalog.
- Verified: verifier confirmed, and added the double-tap path and the note that the existing codes already have rules; judge confirmed and put the double-tap path first.
