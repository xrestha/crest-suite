### SELF-SERVICE-1 [P1] A sign-out that fails on a weak connection leaves the previous employee signed in on a shared phone, so the next person to open Crest Staff sees and acts on their payslips, leave and swaps
- Where: `src/modules/hr/selfservice/SelfServiceHome.jsx:492-496` (signOut ignores the result); `:211-218` (sends to the PIN pad only when there is no session); `src/context/AuthContext.js:387` (same unchecked call in the main app); `src/utils/authFetchTimeout.js:23` (auth calls cut off at 15 s).
- What happens: Sita and Ram share one phone. Sita taps Sign out on weak mobile data. The /logout call fails or hits the 15-second auth timeout; supabase-js then returns `{ error }` without removing the stored session. The code ignores that and shows the PIN pad, so Sita thinks she is signed out. Later Ram taps the Crest Staff icon (start_url `/hr/self-service`): the stored session is still Sita's, and he lands on her Home, her payslips (net pay, SSF number, TDS) and her leave, and can file leave or a TADA claim or accept a swap in her name. Her refresh token is still valid on the server because the logout never reached it.
- Evidence: `async function signOut() { await supabase.auth.signOut(); … navigate(…) }` with no error check. SelfServiceLogin.jsx does not sign out or detect an existing session (it only remembers the client and loads staff, :71-78). auth-js `_signOut` returns early on a session error, and on any /logout error that is not an AuthApiError 401/403/404, before `_removeSession` (library behaviour, installed 2.108.0, not re-read). hss-suite has the identical line (`C:/HSS/src/modules/hr/selfservice/SelfServiceHome.jsx:426-429`). Nothing in CROSS-REPO.md or the rules covers it.
- Status: NEW. Present since S599; missed by S768, which changed where sign-out goes but not how its result is handled.
- Fix: first best-effort unsubscribe push (SELF-SERVICE-5), then `supabase.auth.signOut()`. If it returns an error, remove the auth storage key yourself (the client's storageKey in localStorage) and `window.location.replace` to the PIN pad, so the in-memory client cannot keep the session; show one line there: "You are signed out on this phone. If you use Crest Staff on another phone, it may stay signed in until your manager blocks access." `signOut({ scope: 'local' })` is not a fix on its own: auth-js sends /logout for every scope, so it fails offline the same way. Apply the same fallback to AuthContext.signOut, which reaches shared POS tills and count tablets. File the hss-suite copy in docs/CROSS-REPO.md.
- Confidence: Plausible. The app path is confirmed by reading; the library half is auth-js behaviour as known. Test once on a phone in airplane mode before and after the fix.
- Confirmed 2026-09-30 (S798 stage 1a): the installed supabase-js, run with the network cut, returns `AuthRetryableFetchError` offline and `AuthApiError` on a 500 and keeps the stored session both times; `deviceSignOut.js`'s clear removes it. Fixed in be69499a.
- Verified: verifier confirmed with a correction to the fix (scope 'local' still calls /logout), applied above; judge confirmed and added the 15-second auth timeout, which turns a merely slow connection into a failed sign-out. The outcome is P0-class (another employee's HR data readable and writable); held at P1 because it needs a shared phone, a failed sign-out and a later open.
