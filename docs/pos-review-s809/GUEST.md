- What happens: the Owner replaces the café's logo from POS Setup → Guest Menu on a weak connection. The upload finishes, but the settings save takes longer than its limit. The button goes back to "Replace logo" and nothing is said. If the save landed late, guests now see the new logo while the Owner's card still shows the old one, and the old file is never deleted; if it did not land, the new file sits unused in storage. Remove logo behaves the same way: the dialog closes with no message, and the card may still show a logo that guests no longer see.
- Evidence: `withTimeout` rejects with a `TimeoutError` (`withTimeout.js:21-31`); `saveName` and `saveOrder` in the same file catch it and say "may not have saved", but `handleFile` and `removeLogo` do not, so the rejection escapes as an unhandled promise rejection. CLAUDE.md: "Never claim a failed write did not land. Name the consequence."
