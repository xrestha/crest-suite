**Scope:** `src/modules/hr/**` — 78 source files, ~31,100 lines — the 17 HR routes in `App.js` and the
Crest Staff sign-in (`/hr/self-service/login/:clientId`). Branch `master` at `5a8d425f`, the day after the
S798 HR re-analysis closed (stages 1–4).
**Evidence:** (1) the bundled detector over the module: 3 advisory `design-system-color` hits, all the
documented leave-type fills in `leave/leaveConstants.js` (false positive, as in the baseline); (2) two
file-disjoint source passes — S1 payroll & people, S2 time & staff — each re-measuring every baseline item

**CASA ACAI CAFE**, in two passes — **Modernist Light @1280** (alpha-composited text contrast, accessible

(finalized) as well as the open Ashwin month.
**Write guard:** an in-page `fetch` wrapper installed with `addInitScript` refused every table

Load-time calls seen, all reads: `hr_labour_actuals`, `weather-forecast`, `get_hr_self_service_status`,
`get_client_profile_names`, `get_hr_role_*`, `get_outlet_reaching_logins`, `get_hr_self_service_staff`.
**Baseline:** Appendix C of `2026-09-05T09-39-22Z__crest-suite-all-modules.md` (HR 12/20).
**Not exercised:** no form submitted, no modal opened (Pay Setup's editor, Edit Employee, the TADA claim

## Implementation Integrity Verdict — PASS

The implementation is a coherent, product-specific system, and the class that held HR at 1/4 is closed at
the root rather than per site: Payroll Finalize and Reopen are single database transactions behind a full
re-read (`PayrollRun.jsx:659-775`); every read in all 78 files destructures `error`; conditional writes ask
for `.select('id')` so an RLS 0-row refusal is counted; `ActionError`/`errorLine`/`employeeError` replaced
raw Postgres text on every page; `window.confirm` went from 24 sites to 3 routine single-row deletes;
`HR_REQUEST_STATUS` is the one status vocabulary across five queues and the phone app. Live, the module is
quiet: 0 console errors, 0 failed requests and 0 unnamed controls across 17 routes and every tab.

What holds it at 3 is one shape the money-path fixes did not reach: **an await the user is blocked on, with
no upper bound.** Payroll and Roster adopted `settleWithin` in S798; Crest Staff, Attendance, Final
Settlement and every `useConfirm` run did not — and `ConfirmModal` deliberately makes Cancel, Escape and the
backdrop inert while busy, so one stalled request leaves a dialog only a reload clears. The second shape is
**a consequence sentence the code wrote and the reader never sees** (HR Staff's `invokeDetail` fallback).

## Detailed Findings by Severity

### P1 — Major

**[P1] Primary controls clipped off-screen on a phone, on three money/staff pages**
- **Location** (measured at 390×844, Night, touch, CASA ACAI CAFE):
  - `/hr/staff` — `staff/HrStaff.jsx:603`: the header action group is `display:flex; flexShrink: 0;
    flexWrap: wrap` inside `.page-header--split`. Measured: search 16–196px, Manage Roles 216–348, **+ Add
    Staff 356–464** — 74px past a 390px viewport.
  - `/hr/settlement` — `settlement/FinalSettlement.jsx:829,857`: the inputs card is inline
    `repeat(auto-fill, minmax(220px, 1fr))` holding a `gridColumn: 'span 2'` item; under 456px a span-2 item
    forces an implicit second track. Measured: **Separation Reason** select at 273–449px and the notice
    explanation under it clipped by **59px**.
  - `/hr/payroll` — `payroll/PayrollRun.jsx:1022`: the run's action group is a nested no-wrap flex row that
    `.page-header--split > *` does not reach. Measured on finalized Bhadra 2083: Export, Approval PDF, Reopen
    already end at 359px of a ~374px content box; a DRAFT puts four buttons there (Regenerate, and Finalize
    in place of Reopen), so **Finalize** — the primary action — falls past the edge. (Draft not rendered:
    that needs a generate.)
- **Category:** Responsive
- **Impact:** `.main-content` is `overflow-x: hidden`, so these do not scroll into view — they are not
  there. On a phone a manager cannot add an HR login, cannot read or fully use the reason a leaver is settled
  under, and cannot finalize payroll.
- **Standard:** WCAG 1.4.10 Reflow (AA).
- **Recommendation:** delete `flexShrink: 0` on HR Staff (the S794 rule names exactly this); give
  PayrollRun's inner group `flexWrap: 'wrap'` or flatten it into the wrapping parent; use
  `grid-column: 1 / -1` (spans existing tracks without creating one) or a class with a phone step on Final
  Settlement.
- **Suggested command:** `/impeccable adapt`

**[P1] Roster board text fails AA on both presets**
- **Location:** `roster/Roster.jsx:1716` (shift time line) and `:1721` (hours line) — `<span style={{
  fontSize: 10, color: 'var(--theme-text3)' }}>` inside each `button.roster-cell`, drawn on the shift's own
  fill.
- **Category:** Accessibility / Theming
- **Measured:** Light 3.97:1 (`#6c6868` on `#d3dceb`), 4.19:1 (on `#ebdfcc`), 4.29:1 (on `#cceae0`); Night
  4.11:1 (on `#1f3d32`), 4.30:1 (on `#3f321e`). **120 labels** on the week board, **158** on the month board
  (CASA, Ashwin 2083). Night is otherwise clean on 15 of 17 routes; this is the one dark failure of size.
- **Impact:** the start time and hours are the content of a roster cell — what a manager reads to check
  cover — at 10px, on the screen the week is planned on.
- **Standard:** WCAG 1.4.3 Contrast (Minimum), AA.
- **Recommendation:** re-point the token on the cell rather than editing each span — `.roster-cell {
  --theme-text3: var(--theme-text2) }` (the S794 `tr.row-tinted` solution) — and lift the 10px to 11px
  (10px is DESIGN.md's micro-caps step, not body text).
- **Suggested command:** `/impeccable colorize`

**[P1] The Roster keyboard path is invisible and dead-ends at the shift picker**
- **Location:** `roster/Roster.jsx:1705-1706` (cell inline `outline: inSel ? '2px solid …' : 'none'`, no
  `.roster-cell:focus-visible` rule anywhere); `roster/ShiftPicker.jsx:35-79` and
  `roster/SuggestPopover.jsx:43-104` (`role="menu"` portaled to the end of `<body>`, no focus on open, no
  arrow/Home/End, no focus return).
- **Category:** Accessibility
- **Impact:** S768 built roving focus with arrow keys across the board, but the focused cell's ring is
  removed by the inline `none`, so a keyboard manager on a 40-staff × 32-day board cannot see which cell
  Enter will open. Enter then opens the picker while focus stays on the cell; the other cells are
  `tabIndex=-1`, so Tab leaves the board, and "Morning" / "Clear (Unassign)" sit after every other focusable
  element on the page. `role="menu"` promises arrow keys that do nothing.
- **Standard:** WCAG 2.4.7 Focus Visible (AA), 2.1.1 Keyboard (A).
- **Recommendation:** draw the selection with an inset `box-shadow`, add a `.roster-cell:focus-visible` ring
  pair in `Layout.css`; focus the first `menuitem` on open, roving arrows + Home/End, Tab/Escape close and
  return focus to the cell — or rebuild both popovers on `RowMenu`'s internals, which already do all of it.
- **Suggested command:** `/impeccable harden`

**[P1] Import from machine cannot be started without a mouse**
- **Location:** `attendance/AttendanceImportModal.jsx:211-214` — "Choose file" is a `<label className="btn
  btn-primary">` wrapping `<input type="file" style={{ display: 'none' }}>`.
- **Category:** Accessibility
- **Impact:** a `display:none` input leaves the tab order and a `<label>` is not focusable, so a keyboard or
  switch user who opens Import from machine can reach only the dialog's ×. The whole S775 import (a month of
  attendance) is mouse-only.
- **Standard:** WCAG 2.1.1 Keyboard (A).
- **Recommendation:** the product's own pattern — a real `<button type="button" onClick={() =>
  fileRef.current.click()}>` beside the hidden input (`DishPhotoField.jsx:232-245`). The same shape exists in
  IMS `SalesImportButton.jsx:269` / `RecipeImportButton.jsx:277` [shared pattern].
- **Suggested command:** `/impeccable harden`

**[P1] Crest Staff waits forever on a weak connection**
- **Location:** `selfservice/SelfServiceHome.jsx:287-363` (loaders), `:422, :451, :464, :488, :539` (writes);
  only `unsubscribeFromPush` at sign-out (`:566`) is bounded.
- **Category:** Integrity (availability)
- **Impact:** the employee app is used on a phone link. A stalled `submit_my_leave_request` /
  `submit_my_tada_claim` leaves "Submitting…" disabled, and reopening the sheet does not reset it
  (`openLeave`/`openTada` never clear `submitting`). `swapBusy` is one page-wide flag, so one stalled swap
  answer disables Accept/Decline/Withdraw on every card. A stalled `get_my_roster` sits on "Loading…" with no
  Retry, and an installed iOS PWA resumes into that frozen state. The retries are safe (`tada_duplicate`, the
  leave overlap trigger, `swap_not_pending`), which is what makes bounding them cheap.
- **Standard:** CLAUDE.md — "Wrap any await that blocks the user in `withTimeout()`".
- **Recommendation:** `withTimeout` on reads, `settleWithin` on writes; a timed-out write says "could not
  confirm it was sent — check My requests before sending again"; reset the busy flags on open; a roster load
  timeout falls into `ErrorCard` with Retry.
- **Suggested command:** `/impeccable harden`

### P2 — Minor

**[P2] Blocking dialogs and money buttons with no upper bound**
- **Location:** `src/shared/hooks/useConfirm.js:38-45` [shared] with 18 HR `run:` sites (Leave ×4,
  Overtime ×2, Holidays ×2, TADA ×4, HR Staff ×5, ShiftSettingsPanel ×1); `attendance/AttendanceSheet.jsx:693-696,

## Patterns & Systemic Issues

- **An await the user is blocked on, with no bound.** Payroll and Roster adopted `settleWithin` in S798; the
  rest of the module did not, and the shared `useConfirm` is the multiplier — 18 HR dialogs inherit its
  busy-means-inert design with nothing to end the busy state. Fix it once in the hook, then per page.
- **Inline layout beats the class written to prevent it** — the same finding as the IMS audit, in three new
  shapes: `flexShrink: 0` in a split header (HR Staff), a nested no-wrap group the `> *` rule cannot reach
  (Payroll), and `span 2` inside `auto-fill` (Final Settlement). Grep for all three before the next phone
  sweep.
- **`--theme-text3` has no headroom on any fill.** Roster cells, the active filter chip and the Attendance
  legend all fail for the same reason the IMS tinted rows did. The S794 token re-point (`--theme-text3:
  var(--theme-text2)` on the tinted container) is the proven fix; the next tinted container will need it too.
- **A rule applied to the page that prompted it, not to its siblings.** "Correct figures take the ink"
  (S768) reached PayrollRun only; `nprPaisa` (S798 PAYROLL-7) reached the payslip, not Crest Staff's card;
  S752's draft-marked bank file reached HR Reports, not Festival/Incentives; `RowMenu`'s keyboard model never
  reached the roster popovers. Grep uptake of a rule across the module when it lands.

## Method note (for the next browser sweep)

The Playwright MCP died ("Connection closed") on every call that invoked a function or handler created in an
EARLIER `browser_run_code_unsafe` call — `page.route` handlers, `page.on` listeners, helpers stored on `page`.
That killed the first browser agent and two of this sweep's own calls. What worked: the write guard as an
in-page `fetch` wrapper installed with `page.addInitScript` (no Playwright-side callback), and a stateless
runner fetched from a local static server with `page.request.get` and `eval`'d fresh in every call. Calls that
only define helpers succeed, which is what makes the failure look intermittent.
