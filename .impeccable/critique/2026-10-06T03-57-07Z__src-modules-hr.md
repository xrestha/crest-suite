## Overall Impression

The plumbing is now the best part: accessibility measured clean in both themes and on a phone, and the money path's safety is exemplary. What fails is orientation: the module knows which month you are paying (the strip says Bhadra), then every page forgets it and opens on Ashwin. Biggest opportunity: make the payroll month one module-wide context the strip sets and every page inherits.

## What's Working

1. PayrollMonthStatus — Attendance → Approvals → Payroll → Staff paid → SSF, each with a ✓/△/— mark, a sentence and a deep link; never paints a passed SSF date red because deposits are not recorded (PayrollMonthStatus.jsx:169-176).
2. The register serves the accountant — every payslip row expands into how pay was worked out; hand-typed TDS is named with ↺ back to the calculated figure; flags read "⚠ SSF no. missing".
3. Crest Staff gets the hard states right — "Not published yet" vs "Not scheduled" per day, a per-area error card with Retry, bottom tab bar, next shift skips days off.

## Priority Issues

**[P1] Payroll and HR Reports open on the running month, not the month being paid** — The dashboard strip picks Bhadra, but its "Open Payroll" link is bare /hr/payroll (PayrollMonthStatus.jsx:144); PayrollRun picks the open month (PayrollRun.jsx:258) and reads no ?period=, so the owner lands on "No payroll run for Ashwin 2083 yet" with a primary Generate. HR Reports defaults the same way (B saw the empty state on Ashwin and had to switch to Ashadh). Why: the monthly visit starts on the wrong month; the obvious button starts a mid-month run; the draft looks gone; Reports reads "No payroll run" ~25 days a month. Fix: Payroll + HR Reports accept ?period= and default through the strip's rule (last month until finalized); every strip link carries the period; Generate's empty state on a running month says "Ashwin has N days left"; when another month's draft is open, say so above the select with a link. → /impeccable harden

**[P1] HR's "brass" is red now: "approved, not paid" and "rejected" are both red chips** — HR_REQUEST_STATUS / TADA_REQUEST_STATUS put "decided, money not moved" on badge-yellow, a 12% accent tint with accent-ink text (Layout.css:2741-2744); since S689 the accent is red on both presets, so it sits beside badge-red Rejected. ThemeContext.js:91-95: ink ΔE "is now the ONLY thing keeping 'refused' apart from 'decided, unpaid'". Same red tint on all staff ranks, public holidays, holiday-rate OT, Advances "Active". HR Dashboard paints headcount green and Basic Payroll accent-ink (HrDashboard.jsx:433, 441, 457), against "a correct payroll figure takes the ink". Why: Sita reads an approved claim as refused; a manager scanning queues meets reds meaning three things. Challenges a recorded decision (hr-payroll.md → Colour) written when brass was gold; IMS moved categories off the accent in S796. Fix: categories → badge-gray; "approved, not paid yet" → a non-red slot (grey + ◷, or the purple categorical slot) and re-run the CVD pairs; Roster Draft → RunStatusBadge amber; dashboard figures → ink. → /impeccable colorize

**[P2] Roster says "No active employees found." while still loading** — `loading` is owned only by the roster-rows loader (Roster.jsx:421-449); the staff list loads in a separate init effect (371-398) that never touches it; when rows land first the board renders the empty state (1562-1568). Fix: an init-loading flag; empty state only when init succeeded with zero staff. → /impeccable harden

**[P2] Rules arrive as 11px footnote walls, and working controls drop to 11px** — Leave footnote 7 lines desktop / 15 phone; Overtime, Pay Setup, Gratuity, Attendance help and the Final Settlement caveat (FinalSettlement.jsx:872-877) the same; 158 inline fontSize: 11 across 30 HR files (grep); three toolbar buttons measured at 11px against DESIGN.md's 12px control floor.
